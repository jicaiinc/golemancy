# 需求清单：OAuth 集成修复
> 创建时间：2026-03-08 22:30
> 状态：已确认

## 功能需求
1. Agent 创建时 provider 下拉能看到并选择 OAuth 已连接的 Codex provider（AgentCreateModal）
2. Agent 详情页 provider 下拉能看到并选择 OAuth 已连接的 Codex provider（AgentDetailPage）
3. createProject 自动创建 Main Agent 时，能自动选中 OAuth 已连接的 Codex provider（useAppStore）
4. OAuth 连接成功后，服务端持久化 `testStatus: 'ok'` 到 settings.json，刷新页面后状态保持
5. `CODEX_AUTH_EXTRA_PARAMS` 仅对 Codex provider 生效，不影响未来其他 OAuth provider
6. Settings 页 Test 端点对 OAuth provider 返回有意义的结果（不再发送不兼容的 generateText 请求）

## 技术约束
1. 修复必须从根本上解决问题（服务端持久化 testStatus），而不是在 UI 各处打补丁
2. 所有 `testStatus === 'ok'` 的检查点都必须正确处理 OAuth provider
3. 不破坏现有 API Key provider 的任何功能
4. 遵循项目架构（monorepo 分层、类型定义在 shared 包等）

## 验收标准
1. OAuth 连接成功后 → Settings 页显示 OK → Agent 创建下拉能选到 Codex → Agent 详情页能选到 Codex → Default Model 能选到 Codex
2. 刷新页面后，上述状态保持不变（因为 testStatus: 'ok' 已持久化）
3. 新建 Project 时，如果 Codex 是唯一可用 provider，Main Agent 自动使用它
4. 现有 API Key provider 的添加、测试、使用不受影响
5. pnpm lint + pnpm test 全部通过
